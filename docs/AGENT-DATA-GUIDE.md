# Инструкция для агента: добавление партий и кандидатов

Документ описывает **текущую** схему данных (schema_version 2.0, состояние на 10.09.2026) и правила, по которым
корпус можно расширять без нарушения редакционной модели.

Схема не только описана здесь, но и исполняется: файлы в `schema/` — формальный контракт, `npm run validate`
проверяет по нему оба набора плюс правила, которые схемой не выразить. Правка, не проходящая валидатор, не сдаётся.

Правила приёма внешних правок — в [`CONTRIBUTING.md`](CONTRIBUTING.md). Этот документ описывает, **как** заполнять
поля; тот — **что** вообще принимается и почему.

Читать целиком перед первой правкой. Не менять схему без отдельного задания.

---

## 0. Принципы (нарушение любого — отклонение правки)

1. **Нейтральность.** Сайт не рекомендует, не ранжирует, не считает «совпадение». Ни одна формулировка не должна содержать оценочных прилагательных о партии или человеке в целом («опасный», «надёжный», «популист»). Оценка допустима только к **конкретному эпизоду** и только с `kind: assessment`.
2. **Три сущности разделены:** факт (`fact`), заявление участника (`position`), редакционная интерпретация (`assessment`), пробел в данных (`uncertainty`). Нельзя смешивать их в одной записи.
3. **Каждый тезис имеет источник** или явно помечен как неподтверждённый. Придумывать источники, ссылки, даты — запрещено. Если источник не найден, это `uncertainty` с `source_ids: []`.
4. **Отсутствие данных — это результат.** Кандидат с `profile_depth: limited` и честным `unknowns` лучше, чем додуманное досье.
5. **Не переносить позицию лидера на список** и позицию прошлой партии на новый союз без прямого источника. Если переносите — это `assessment` с оговоркой.
6. **Русский язык, без латиницы в прозе** (кроме названий СМИ и брендов). Иврит только в полях `name_he`.
7. **Один файл — одна правда.** Данные живут только в `public/parties.json` и `public/candidates.json`. Тот же файл отдаётся читателю по прямой ссылке и импортируется приложением, поэтому копий заводить нельзя.

### 2.2 `Source`

```jsonc
{
  "id": "hendel-union",             // латиница, kebab-case, уникален во всём каталоге
  "title": "JDN · Объединение Хенделя и Зелихи",   // «Издание · О чём», по-русски
  "url": "https://…",               // реальный URL, проверенный агентом в момент accessed_at
  "published_at": "2026-09-06",     // ISO YYYY-MM-DD или null, если дата не установлена
  "accessed_at": "2026-09-10",      // ISO, дата, когда агент открыл ссылку
  "type": "media",                  // см. enum ниже
  "date_kind": "exact",             // exact | month | accessed_only — см. ниже
  "language": "he"                  // he | ru | en | mixed (необязательное; добавлять, если знаете)
}
```

`type` ∈ `party` (сайт/программа партии) · `institutional_media` (Кнессет, ЦИК, гос. каналы) · `media` (новости) ·
`news` (синоним `media`, легаси — новые записи помечать `media`) · `interview` · `poll` · `research` (IDI, INSS, академические) ·
`analysis` (аналитические колонки, агрегаторы) · `investigation` (расследования).

Правила источников:
- Предпочтение: первоисточник (программа, официальное заявление, стенограмма) > институциональное СМИ > крупное СМИ > колонка/блог. Соцсети допустимы только как `interview`/`position` с прямой ссылкой на пост.
- Для спорных тезисов (флаги красные/жёлтые) — **минимум два независимых источника**, один из которых даёт позицию самого человека/партии, если она есть (см. пару `stern` / `stern-response`).
- `date_kind` описывает, что именно известно о дате: `exact` — полная дата (`YYYY-MM-DD`); `month` — известен только месяц (`YYYY-MM`, например месячный выпуск журнала); `accessed_only` — дату публикации установить не удалось, и тогда, и только тогда, `published_at: null`. Такой источник интерфейс показывает только с датой проверки.
- `published_at: null` допустим только для живых страниц (сайт партии). У статьи дата есть всегда — искать в URL, в `<meta>`, в тексте.
- Один источник — одна запись. Не создавать `ndi-2`, если `ndi` уже описывает ту же страницу.

### 2.4 `Claim` — базовая единица (используется везде)

```jsonc
{
  "text": "…",                      // 1–2 предложения, ≤ 240 символов; первое — суть, второе — оговорка
  "kind": "position",               // fact | position | assessment | uncertainty
  "source_ids": ["hendel-union"],   // [] допустимо ТОЛЬКО при kind: uncertainty
  "verification": "verified",       // verified | partial | unverified
  "confidence": "confirmed"         // confirmed | limited — шкала двухступенчатая
}
```

Семантика:

| kind | что это | source_ids | типичные verification/confidence |
|---|---|---|---|
| `fact` | проверяемое событие/биография: занимал пост, голосовал, подписал | ≥1 | verified / confirmed |
| `position` | что партия или человек **заявляет** сейчас | ≥1 | verified / confirmed |
| `assessment` | редакционная интерпретация факта (влияет ли на доверие, согласованность) | ≥1 (факт, на который опирается) | verified / confirmed |
| `uncertainty` | мы искали и не нашли ясной позиции | [] или ссылки на то, где искали | unverified / limited |

`verification`: `verified` — источник открыт и подтверждает текст дословно или по смыслу; `partial` — источник подтверждает часть тезиса (напр., позицию лидера, но не списка); `unverified` — прямого источника нет.
`confidence`: `confirmed` — есть открытый источник, подтверждающий текст; `limited` — подтверждение косвенное, устное или отсутствует. Третьей ступени нет намеренно: ни одно утверждение корпуса не дотягивало до «высокой» уверенности, а держать недостижимый уровень в схеме значит обещать читателю несуществующую точность.

Правило без исключений: `assessment` без источника не бывает. Оценка, под которой нет факта, понижается до `uncertainty`; валидатор это проверяет.

### 2.5 `Position` = Claim + `topic` + `value`

```jsonc
{ "topic": "netanyahu", "value": "replace", …Claim }
```

`value` — машиночитаемый ярлык позиции внутри темы. Словарь допустимых значений живёт **в данных**:
`topics[].values` отображает `value` в короткую русскую подпись, которую матрица показывает в ячейке.
Значение `unknown` подписывается глобально («Не установлено») и в `values` не объявляется.

Действующий словарь (`public/parties.json` → `topics[].values`):

| topic | value → подпись |
|---|---|
| netanyahu | `replace` Смена правительства · `recommend` Рекомендует Нетаньяху |
| service | `universal` Служба для всех |
| religion | `local` Решает община и муниципалитет · `civil` Гражданский брак и шаббат |
| olim | `narrow_eligibility` Сузить круг имеющих право · `keep_eligibility` Сохранить право по статье 4А · `civil_status` Гражданский статус без гиюра · `civil_status_integration` Гражданский статус и меры интеграции |

Про тему `olim` отдельно. «Параграф о внуке» — не отдельная статья: право ребёнка и внука еврея, а также их супругов, живёт в **статье 4А**, добавленной в закон в 1970 году, и затрагивает около 400 тысяч репатриантов из бывшего СССР и их потомков, не признанных евреями по галахе. В текстах пишем «статья 4А», а «параграф о внуке» — только в кавычках как разговорное имя.

Две нижние ступени шкалы (`narrow_eligibility`, `keep_eligibility`) объявлены, но в этом сравнении никем не заняты. Это не ошибка: шкала обязана показывать, что позиция «сузить» существует и что среди шести списков её никто публично не занял. Убирать необъявленные ступени нельзя — иначе исчезнет сам масштаб.
| courts | `independence` Независимость суда · `constitution` Конституция и конституционный суд |
| security | `force_and_diplomacy` Сила и дипломатия · `international_transfer` Международное управление Газой · `regional_alternative` Региональная альтернатива ХАМАС · `military_primacy` Военное решение |
| palestine | `two_states` Два государства |
| arab | `conditional` Сотрудничество под условием · `exclude` Коалиция без арабских партий · `partnership` Гражданское партнёрство |
| economy | `competition` Конкуренция и стоимость жизни · `social` Социальное равенство |
| selection | `leader` Решение лидеров · `primaries` Праймериз |

Два жёстких правила, обе проверяет валидатор:

- `value: "unknown"` и `kind: "uncertainty"` ставятся только вместе. Если позиция заявлена, но её условия не подтверждены, это по-прежнему `position` с осмысленным `value` и `verification: partial`, а не `unknown`.
- `value` не повторяет имя темы: `security: "security"` — тавтология, ничего не сообщающая читателю.

Новое значение вносится сразу в `topics[].values` вместе с подписью и в эту таблицу.

#### Шкала темы (`topics[].axis`)

Шесть тем из девяти дополнительно объявляют шкалу — она питает режим «Шкалы» в матрице:

```jsonc
"axis": {
  "low":   "политическое урегулирование",   // название полюса в нуле
  "high":  "военное решение",               // название полюса в единице
  "order": ["regional_alternative", "international_transfer",
            "force_and_diplomacy", "military_primacy"],
  "note":  "Порядок — по тому, сколько в ответе односторонней силы и сколько…"
}
```

`order` утверждает **порядок значений и только его**. Позиция на шкале считается как индекс,
делённый на длину: равные промежутки между ступенями — вычислительная условность, а не заявление
о том, что одна позиция «вдвое дальше» другой. Придумывать веса вместо порядка нельзя.

`note` обязателен. Это одна-две фразы о том, **по какому признаку построен порядок** — именно их
читатель и будет оспаривать: не «правильна» ли позиция, а верно ли она стоит между соседями. Шкала
без объяснения читается как оценка, а оспорить можно только сформулированное утверждение. Если
признак не формулируется одной фразой — скорее всего, порядка на этой теме нет и `axis` ей не нужен.

Полюса называются **описанием позиции, а не оценкой**: «военное решение», а не «жёсткая линия»;
«коалиция без арабских списков», а не «изоляционизм». Читатель должен видеть измерение, а не приговор.

Какой конец назван нулём — **не утверждение**: шкалы никогда не складываются между собой, каждая
строка читается сама по себе, и от переворота любой оси в данных не изменится ни одно число.
Существенно другое: оси намеренно **не смотрят в одну сторону**. На одних дальний конец ближе
правому избирателю, на других — левому, поэтому «все точки справа» не значит ничего. Добавляя
шкалу, проверьте это свойство: если после вашей правки какой-то список окажется у одного полюса
по всем осям, картинка начнёт читаться как рейтинг.

Темы без `axis` оставлены такими намеренно, и это не недоделка:

| тема | почему нет шкалы |
|---|---|
| `service` | все известные позиции совпадают — шкала выродилась бы в точку |
| `palestine` | известна одна позиция из шести |
| `courts` | `independence` и `constitution` не выстраиваются на одной прямой: обе защищают суд, но по-разному. Разведение на две темы рассматривалось и отклонено — см. A13 в `BACKLOG.md` |

Добавлять шкалу теме, где значения не упорядочены, — худшее, что можно сделать с этим набором:
порядок станет утверждением, которого никто не проверял. Если сомневаетесь, оставьте без `axis`:
тема останется в матрице и просто не попадёт в шкалы.

### 2.6 `Flag` = Claim + `color` + `title`

```jsonc
{ "color": "yellow", "title": "Устойчивость союза", …Claim }
```

- `color`: `red` — задокументированное нарушение обещания или серьёзный спорный эпизод с последствиями; `yellow` — противоречие, разворот, открытый вопрос; `green` — поступок, подтвердивший заявленный принцип ценой для себя.
- `title` ≤ 40 символов, называет эпизод, не человека («Коалиционный разворот», не «Ненадёжный»).
- Флаг всегда `kind: assessment` (это редакционная пометка), опирается на `fact`-источники и потому обязан иметь `source_ids`.
- `Flag` в этом виде существует только на уровне партии. У кандидата отдельного массива флагов нет: цвет ставится прямо на запись в `strengths` или `concerns` (см. 3.1).
- Флаг относится к **эпизоду**, не к человеку целиком; текст должен позволять читателю не согласиться.

### 3.1 `Candidate`

```jsonc
{
  "id": "yashar-farkash-hakoen-orit",  // стабильный ключ <партия>-<фамилия>-<имя>, латиницей; см. ниже
  "position": 3,                    // место в поданном списке (источник lists) — поле, а не ключ
  "name": "Орит Фаркаш-Хакоэн",     // русская транскрипция как в русскоязычных израильских СМИ; дефисы сохранять
  "name_he": "אורית פרקש הכהן",     // необязательное; ставить только при наличии источника, не транслитерировать наугад
  "bio": "Юрист, бывшая глава Управления электроэнергетики, министр и депутат.",   // 1 предложение, ≤ 110 символов, только должности/роли
  "summary": "…",                   // 1–2 предложения: кто это и что представляет в списке; для limited == bio
  "profile_depth": "substantive",   // substantive | basic | limited (см. 3.2)
  "source_ids": ["lists", "yashar-team"],   // откуда взяты место и bio; минимум `lists`
  "verification": "verified",
  "confidence": "confirmed",
  "strengths": [ ProfileClaim, … ], // «подтверждающие поступки»: что в биографии подтверждает заявленную линию
  "concerns": [ ProfileClaim, … ],  // «спорные эпизоды и риски»: что требует внимания
  "criteria": [ CriterionNote, … ], // связь с темами сайта
  "trust_notes": [ TrustNote, … ],  // отдельная рубрика: доверие, прозрачность, согласованность союза
  "unknowns": [ "…" ]               // 1–3 строки: что именно не найдено; никогда не пусто
}
```

`id` — стабильный ключ: `<party.id>-<фамилия>-<имя>` в механической транслитерации, только `[a-z0-9-]`.
Он не меняется при пересортировке списка, и именно на него ссылается адресная строка (`?c=<id>`). Менять `id`
существующего кандидата нельзя: это ломает разосланные ссылки. При совпадении добавляется числовой суффикс.

`ProfileClaim` = Claim + `title` (≤ 50 символов) + необязательный `color`.
Отдельного массива флагов у кандидата нет: отмеченный эпизод — это обычная запись в `strengths` или `concerns`,
у которой проставлен `color`. `green` живёт только в `strengths`, `red` и `yellow` — только в `concerns`.
Строка списка показывает самый серьёзный из проставленных цветов: красный важнее жёлтого, жёлтый важнее зелёного.

`CriterionNote` = Claim + `topic` + `label`, где **`topic` обязан быть одним из `topics.id`**
(`netanyahu, service, religion, courts, security, palestine, arab, economy, selection`), а `label` — короткая
подпись рубрики в досье (не обязана дословно повторять `topics.label`).

`TrustNote` = Claim + `label`, без `topic`. Доверие, прозрачность и согласованность союза — это свойства
человека и коалиции, а не политический критерий: в матрицу они не попадают и живут отдельной рубрикой досье.

### 3.2 Уровни глубины

| profile_depth | минимум |
|---|---|
| `substantive` | summary ≠ bio; ≥1 strength **и** ≥1 concern или flag; ≥2 criteria; ≥2 источника, хотя бы один — не список кандидатов |
| `basic` | summary ≠ bio; ≥1 strength; ≥1 criterion; unknowns конкретный (что искали); ≥1 источник кроме `lists` |
| `limited` | bio; unknowns; источник `lists` (+ сайт партии, если есть). strengths/concerns/criteria/trust_notes — пустые массивы |

Не повышать уровень ради «красоты». Если после часа поиска материала нет — `limited` с указанием, где искали:
`"unknowns": ["Проверены: сайт партии, N12, Ynet, Wikipedia (he). Публичных позиций по темам сайта не найдено."]`.

## 4. Процедура: добавить партию

1. **Получить задание** с `id`, ивритским названием, русским названием, лидерами, обоснованием включения (почему этот список входит в выборку — выборка не случайна, решение принимает человек).
2. **Собрать источники** (минимум): страница списка в `lists` (Канал Кнессета) или другой официальный источник поданного списка; сайт/программа партии; последний опрос N12 (`poll-n12`) — число мандатов; IDI-страница партии, если есть; 1–2 интервью лидера за последние 60 дней.
3. **Зарегистрировать источники** в `parties.sources` (раздел 2.2). Проверить, что `id` не занят.
4. **Заполнить 9 позиций** строго в порядке `topics`. Для каждой: найти прямое заявление → `position` + `value`; если нашли только позицию лидера, а не списка → `position`, `verification: partial`, текст с оговоркой; если ничего → `uncertainty`, `value: unknown`, текст «В проверенных материалах (перечислить) ясной позиции не найдено».
5. **`trust_risk`** — одна `assessment`-запись: что структурно ограничивает проверку обещаний (новый список, нет истории голосований, союз двух структур и т. п.). Не «партия ненадёжна».
6. **`flags`** — 0–3 эпизода по правилам 2.6. Красный флаг — только при двух источниках.
7. **`default_seats`** из `poll-n12` (или обновить `poll-n12` на более свежий опрос **для всех партий сразу**, не для одной). `audit_depth` = число кандидатов, которых вы опишете на шаге 8.
8. **Кандидаты**: раздел 5. Минимум — вся проходная зона по опросу + 2 места запаса; минимум 5.
9. **Цвет**: выбрать из палитры приглушённых (насыщенность ≤ 45%), проверить, что визуально отличается от 6 существующих: `#334dbb (yashar) #227b89 (together) #5963a4 (beytenu) #89527c (democrats) #a66b2c (reservists) #6c7058 (amcha)`. Не использовать красный/жёлтый/зелёный оттенки флагов.
10. **Тексты, зашитые под число партий** (сообщить в отчёте, не править без задания): `app/page.tsx` — интро «Шесть списков…» и абзац «Почему именно эти шесть списков» на вкладке «Методика»; `README.md` — список партий и число профилей. Вёрстка под число партий больше не зашита: задержка анимации карточек считается из `--i`, а матрица подстраивается сама.
11. **Проверка** (раздел 6) и отчёт (раздел 7).

## 5. Процедура: добавить или углубить кандидата

1. Убедиться, что партия есть в обоих файлах и `position` свободна (или вы углубляете существующую запись — тогда не менять `position`, `name`, `bio` без источника).
2. Источники по кандидату: место в списке (`lists`), страница команды на сайте партии, ивритская Википедия (как навигатор, **не как источник** — цитировать первоисточник, на который она ссылается), СМИ за последние 5 лет по имени на иврите и по-русски.
3. Написать `bio` (роли), `summary` (кто и что представляет в списке — без оценок).
4. `strengths`: поступки, а не качества. «Возглавлял ЦАХАЛ» — факт; «сильный лидер» — запрещено.
5. `concerns`: эпизоды с источником. Обязательно искать ответ/объяснение самого человека и прилагать (второй источник). Без ответа — `confidence: low`.
6. `criteria`: 1–3 записи, `topic` из `topics.id`. Это `assessment` о том, как биография соотносится с темой; если позиция человека по теме заявлена прямо — `position`. Заметки о доверии и прозрачности идут не сюда, а в `trust_notes`.
7. `unknowns`: конкретно. «Не найдена позиция по судебной реформе после 2023 г.» — хорошо; «Мало данных» — плохо.
8. Проставить `profile_depth` по таблице 3.2 — по факту наполнения, не по желанию.
9. `id` — по правилу из 3.1; для существующей записи не менять никогда.
10. Проверить (раздел 6) и отчитаться (раздел 7).

Названия партий сверяются по русскому списку партий (источник `lists-ru`), а не переводятся с иврита самостоятельно: иврит допускает субстантивированное прилагательное без существительного (`והכלכלית` — «и экономическая»), а в русском такой оборот повисает.

Имена людей: транскрипция как в русскоязычных израильских СМИ (Вести, NEWSru.co.il, Детали). Если вариантов несколько — тот, что чаще, и упомянуть альтернативу в отчёте. Дефисы в двойных фамилиях сохранять. Феминитивы: **не использовать** («юрист», «директор», «депутат» для всех) — пока не принято другое правило (BACKLOG C7).

## 6. Самопроверка перед сдачей

```bash
npm run validate
```

Проверяются: структура по `schema/*.schema.json`; существование каждого `source_id`; отсутствие `assessment`,
`fact` и `position` без источника; полнота позиций (по одной на каждую тему, без повторов); словарь `value`
и связка `unknown` ↔ `uncertainty`; равенство `audit_depth` длине списка кандидатов; сплошная нумерация мест;
уникальность `id` кандидатов; календарная корректность дат и их согласованность с `date_kind`; совпадение
`meta.as_of` в обоих файлах; отсутствие неиспользуемых источников в каталоге.

Вывод на здоровом корпусе — одна строка со сводкой. Любая другая строка блокирует сдачу: известных
«ожидаемых» ошибок в наборе больше нет, поэтому чужих сообщений в выводе быть не может.

Полный прогон вместе с типами и линтером:

```bash
npm run check
```

Часть редакционной модели тоже проверяется машиной, потому что корпус открыт для правок:

- **Оценочные ярлыки** («популист», «предатель», «опасный», «лучший» и остальной закрытый список в `scripts/validate-data.mjs`) отклоняются автоматически. Сравнение идёт по токенам, а не по подстроке, поэтому «безопасность» проходит, а «опасный» — нет.
- **Потолки длины** полей: `text` 280, `summary` 320, `bio` 140, `descriptor` 70, `title` 90, `label` 70. Это защита от манифеста в поле карточки, а не стилистика; рекомендованные значения строже — `text` ≤ 240, `bio` ≤ 110, `descriptor` ≤ 60, `title` ≤ 40/50.
- **Ссылки только по https.**

Смысл валидатор не проверяет. Отдельно, руками:

- Каждый новый URL открыт агентом в день `accessed_at`, и страница действительно содержит то, на что ссылается текст. Если страница закрыта для инструмента (`kan.org.il` отдаёт 403), текст можно взять у человека — но в отчёте это указывается прямо, а `accessed_at` означает дату сверки, а не автоматической загрузки.
- Ни одного «в беседе» без источника: устное сообщение без ссылки — это `uncertainty`, а не факт.
- Оценка относится к эпизоду, а не к человеку, и сформулирована так, что читатель может с ней не согласиться.
- Источник действительно независим: два материала одного издания по одному пресс-релизу — это один источник.

## 8. Границы, которые агент не переходит сам

- **Состав выборки.** Новые партии не добавляются, пока человек не подтвердил включение: шесть списков — осознанный редакционный выбор, а не «все, кто подал списки». То же касается снятия партии из выборки и смены `control`.
- **Направление шкал.** `topics[].axis` — редакционное решение: какой конец оси считать нулём и в каком порядке идут значения. Не менять правкой данных и не добавлять шкалу новой теме без отдельного задания.
- **Схема.** `topics`, набор `kind`, шкалы `verification` и `confidence` не расширяются правкой данных. Нужна новая тема или ступень — это отдельное задание с правкой `schema/`, валидатора и этого документа в одном коммите.
- **Смена опроса.** `meta.poll` и все `default_seats` обновляются только вместе. Подставить свежее число одной партии — значит смешать в таблице два разных опроса.
- **Красный цвет.** Ставится только при двух независимых источниках, один из которых даёт ответ или объяснение самого человека, если оно существует.
- **Феминитивы.** Пока не используются («юрист», «директор», «депутат» для всех) — до отдельного решения (BACKLOG C7).
- **`id` кандидата и партии.** Не переименовываются: на них ссылаются разосланные ссылки вида `?c=<id>` и `?party=<id>`.
