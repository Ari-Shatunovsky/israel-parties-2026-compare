# Выборы в Израиле 2026: партии и люди

Интерактивный русскоязычный инструмент для нейтрального сравнения партий и кандидатов на выборах в Кнессет 26-го созыва.

Сайт не рассчитывает политическое «совпадение», не ранжирует партии и не рекомендует, за кого голосовать. Он разделяет проверяемые факты, заявления участников, редакционные оценки и пробелы в данных.

## Что внутри

- карточки шести избирательных списков;
- сравнительная матрица по одинаковым политическим критериям;
- сценарий проходных мест, управляемый числом мандатов;
- 71 профиль кандидата;
- подробные досье с подтверждающими поступками и спорными эпизодами;
- явные уровни проверки и уверенности у каждого тега доказательства;
- ссылки на источники и даты доступа;
- машиночитаемые наборы данных в JSON со схемой и валидатором;
- состояние интерфейса в адресной строке: любой экран можно переслать ссылкой.

Сравниваются:

- `ישר!` («Яшар») — Гади Эйзенкот;
- `ביחד` («Беяхад») — Нафтали Беннет и Яир Лапид;
- `ישראל ביתנו` («Наш дом Израиль») — Авигдор Либерман;
- `הדמוקרטים` («Демократы») — Яир Голан;
- `המילואימניקים והכלכלית` («Резервисты и Экономическая») — Йоаз Хендель и Ярон Зелиха;
- `עמך ישראל` («Амха Исраэль») — Офер Винтер, как контрольный правый вариант.

Русские написания в скобках — те же, что в `name_ru` в данных; расхождений между README и корпусом быть не должно.

## Данные

- [`public/parties.json`](public/parties.json) — партии, лидеры, позиции, риски доверия и каталог источников.
- [`public/candidates.json`](public/candidates.json) — порядок списков, биографии и досье кандидатов.

Эти два файла — единственный источник правды: тот же файл отдаётся читателю по прямой ссылке и импортируется приложением.

Каждое содержательное утверждение хранит:

- `kind`: факт, позиция, редакционная оценка или установленный пробел;
- `verification`: `verified`, `partial` или `unverified`;
- `confidence`: `confirmed` или `limited` — шкала двухступенчатая намеренно, третьей ступени в корпусе нет;
- `source_ids`: ссылки на записи в каталоге источников.

Оценка без источника в наборе невозможна: она понижается до пробела. Глубина кандидатских профилей обозначается отдельно: `substantive`, `basic` или `limited`. Недостаток публичного материала сохраняется как результат исследования, а не заполняется предположениями.

Схема набора описана формально в [`schema/`](schema/) и проверяется скриптом:

```bash
npm run validate
```

Проверяются структура, существование каждого `source_id`, полнота позиций по темам, совпадение глубины аудита с длиной списка кандидатов, календарная корректность дат и отсутствие неиспользуемых источников.

## Локальный запуск

Требуется Node.js 22.13 или новее.

```bash
npm install
npm run dev
```

Сборка:

```bash
npm run build
```

Типы, линтер и проверка данных одной командой:

```bash
npm run check
```

## Обновление данных

Досье кандидатов и позиции партий правятся прямо в `public/parties.json` и `public/candidates.json`, после чего запускается `npm run validate`. Правила расширения корпуса — какие источники годятся, чем факт отличается от оценки, когда пробел остаётся пробелом — собраны в [`docs/AGENT-DATA-GUIDE.md`](docs/AGENT-DATA-GUIDE.md). Открытые задачи по проекту — в [`docs/BACKLOG.md`](docs/BACKLOG.md).

## Правки со стороны

Проект принимает исправления, но только с источником: правила и список того, что закрывается без обсуждения, — в [`docs/CONTRIBUTING.md`](docs/CONTRIBUTING.md).

Первый фильтр — машинный. `npm run validate` стоит в CI и отклоняет утверждение без источника, оценочный ярлык о человеке или партии, текст, вылезающий за формат карточки, и любое нарушение схемы. Он не решает, кто прав; он снимает самый дешёвый способ протащить агитацию — назвать человека словом вместо разбора конкретного эпизода.

## Методика и ограничения

Позиция партии фиксируется по актуальной программе или прямому публичному заявлению. Биография подтверждает опыт человека, но сама по себе не предсказывает будущее голосование. Цветная пометка относится к конкретному эпизоду, а не к человеку целиком.

Списки, опросы и заявления могут меняться. Дата актуальности набора хранится в поле `as_of`; дата проверки каждого источника — в `accessed_at`.
